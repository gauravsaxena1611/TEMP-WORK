Background (where we are today)
Our users currently prepare their input data (extracting from EDW and other sources) and place it into their AHUB directories, then manually download and re-upload it into CRC. The legacy EUCs already read from AHUB via a secure Python SFTP (PySFTP) connection, server-to-server, so the data never lands on a local machine.

What we'd like to do
Use AHUB as the landing zone / starting point for our tool's input files. Users would drop their prepared file into AHUB, and CRC would read it directly via a secure Python SFTP connection into our environment — no local downloads, no copying PII into a database. Our preferred model is a per-user, entitlement-based connection (a user authenticates with their own AHUB credentials and sees only the files/folders they're entitled to — similar to how SAS Studio already surfaces a user's AHUB directories), rather than one shared repository.

Is our understanding correct, and is this pattern supported today — can another application read from AHUB this way?
